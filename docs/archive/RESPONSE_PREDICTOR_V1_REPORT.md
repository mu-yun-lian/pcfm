# PCFM 统一人物响应预测内核 v1

## 结论

本阶段把网页普通对话从“检索最相似问答并复制答案”改接到统一的非生成式人物响应预测内核。产品闭环和数据门禁已实现；现实人物响应预测准确性尚未获得确认性证据。

## 审计发现与修正

- 旧 `conversation_mvp.py` 没有调用人物 `fit/predict/update` 思路，而是用 `_best_support` 直接选择问答或资料片段作为回答；现已停止用于人物预测，只保留在用户主动触发的现实回答对照。
- 旧消息历史只保存不建模；现在最近六条用户和模型消息进入固定情境编码器，模型生成历史明确标记为 `model_generated_context`，只用于本轮连贯，不能进入证据或训练集。
- 旧置信度是相似度启发式分数；现在来自多头参数不确定性与局部证据支持，但尚未校准，界面明确显示“未校准置信度”。
- 旧优化主要改变检索资料集合；现在来源先成为 `OptimizationCandidate`，审核、角色隔离和留出非退化检查通过后才拟合新人物响应模型版本，旧版本可回退。
- 普通删除原来物理删除人物目录；现在先移动到本地归档，只有归档内人物可以永久删除。

## 统一入口

`pcfm.response_prediction.ResponsePredictionKernel` 是训练、部署预测和评测共用入口：

1. 将已确认、可归因的本人直接问答转为 `pcfm-response-event-v1`；
2. 使用固定 72 维哈希情境编码，不调用生成式模型；
3. 使用与早期人物内核同源的 MAP Logistic 数值核拟合回应动作和立场多头；
4. 人物真实证据只生成观点、理由和不确定性候选，统一预测器负责采用排序；
5. 输出结构化回答、适用性、拒绝原因、组件状态和内容摘要；
6. 生成独立冻结表达合同，经人物表达渲染器处理；渲染失败返回中性内容。

## 数据边界

只有审核后确认说话人与人物姓名或别名一致、且存在明确问题和回答的事件可以作为训练标签。非问答资料、说话人不匹配、自动推断和模型生成内容只能进入未验证候选。训练、适用性、特征发现、候选选择、封存验证、上线监测和外部现实对照角色互斥。

目前支持文本粘贴、TXT、Markdown、HTML、PDF、SRT/VTT、JSON、CSV 和网页地址。按人物姓名自动联网搜索、OCR、音视频转写没有可用后端，产品会报告未配置。

## 模块状态

- `active`：响应事件管线、人物 MAP 适配、多头预测、检索候选召回、文本局部适用性门禁、受约束表达渲染。
- `experimental`：群体先验（只有多人物池足够时激活）、动态状态、机制修正、Empirical Bayes。
- `registered`：认知数值特征接口。
- `rejected`：HyperNetwork、Person-Issue、Joint Core；不会静默进入当前预测。

早期二元模型、动态状态和机制比较的证据与版本基础设施仍保留。因为它们的数据合同是结构化二选一，不能在没有新响应事件验证的情况下直接解释自然语言回应，故目前不激活。

## 诚实状态

- 数据管线：完成最小可运行闭环。
- 模型可训练：完成。
- 产品闭环：完成本地最小闭环。
- 表达层语义结构门禁：已接入；风格盲测未评估。
- 历史立场复现：未验证。
- 人物特异性响应预测：证据不足。
- 确认性验证：未通过，原因是没有独立、严格时间隔离的真实人物封存问答集。

工程测试通过只能证明上述路径按合同运行，不证明正确人物模型优于错误人物、群体、检索和人物历史频率基线。系统已经提供统一基线比较结果结构；在足够的封存样本到来前，发布门禁固定为 `not_passed`。
