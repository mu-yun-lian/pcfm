## 三、SQLite 读路径最终形态

- **version**：默认从 SQLite `data` 列返回完整版本（与 JSON 全量比对一致才返回）。
- **state / session**：表字段不完整（缺 rollback_history / message_count 等），做「SQLite 对比 + 不一致自愈」，仍返回 JSON。
- **source_counts**：light 列表读 SQLite 聚合。
- **message**：仍读 JSON（本节不动，见第四节）。
- 回退与自愈：SQLite 为空/读错/不一致时告警 + 回退 JSON + 触发 `_sync_*` 自愈；设 `PCFM_SQLITE_READ_PRIMARY=0` 立即回退影子模式。

## 四、主线第 5 步 5.4（message 读路径）立项说明

**目标**：把 message 读路径从 JSON 切换到 SQLite 优先，使消息元数据与正文都具备「SQLite 优先 + JSON 回退 + 不一致自愈」。

### 前置改造（当前阻塞点）

1. `_sync_messages_to_sqlite` 目前只镜像**活动会话**的消息；需改为覆盖**所有会话**（每个会话文件同步一次）。
2. `message` 表现有列是「平铺索引列」（role/text/status/answer_status/structured_prediction 等），**无完整消息 dict 列**；需新增 `data` 列（存完整消息 dict），与 version 表 `data` 列同源。
3. `message_repo` 新增反序列化读方法（`list_full_by_session`，从 `data` 列读完整消息）。
4. 会话切换/删除后 message 表需同步清理（当前 `delete_by_session` 已具备，需扩展为全会话一致性）。

### 实施步骤（复用主线 5.1–5.3 的成熟模式）

1. schema 迁移：`ALTER TABLE message ADD COLUMN data`（`_ensure_schema_migrations` 扩展）。
2. `_sync_messages_to_sqlite` 覆盖所有会话，写 `data` 全量列。
3. `read_path.py` 新增 `_read_messages(session_id)`（影子对比 → 灰度返回 SQLite → 默认开启），与现有 `_read_versions` 同构。
4. `consistency_check.py` 扩展 message 全量对比。
5. 灰度验收：3 轮回归 + consistency-check 10 次 0 不一致 + 人工不一致演练 + 性能复测，再默认开启。

### 验收标准

- 消息读路径默认从 SQLite 返回（一致时），JSON 回退 + 自愈；
- 会话切换/删除后 message 表无孤儿、无陈旧；
- 全量回归 + consistency-check + 性能达标；
- 13→12 项 skip 不变（不新增 skip）。

### 风险与回滚

- 镜像未覆盖写路径 → 影子先行、不一致只告警不改行为；
- 误开 → `PCFM_SQLITE_READ_PRIMARY=0`；
- 任意阶段回退上一 commit/tag。
